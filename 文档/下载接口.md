# 下载入口与版本接口

GitHub Releases用于分发APK；应用本身不访问这些接口，不自动联网更新。无需搭建额外下载服务器。

发布账号为 `cheems-678`，仓库为 [fitness-diary](https://github.com/cheems-678/fitness-diary)。

| 用途 | 地址 |
|---|---|
| 版本列表 | [Releases](https://github.com/cheems-678/fitness-diary/releases) |
| 最新版本说明 | [最新Release](https://github.com/cheems-678/fitness-diary/releases/latest) |
| 最新APK固定入口 | [fitness-diary.apk](https://github.com/cheems-678/fitness-diary/releases/latest/download/fitness-diary.apk) |
| 指定1.1.0安装包 | [v1.1.0 APK](https://github.com/cheems-678/fitness-diary/releases/download/v1.1.0/fitness-diary.apk) |
| SHA-256文件 | [SHA256SUMS.txt](https://github.com/cheems-678/fitness-diary/releases/latest/download/SHA256SUMS.txt) |
| 最新版本JSON | [Releases API](https://api.github.com/repos/cheems-678/fitness-diary/releases/latest) |

固定APK地址会重定向到最新正式Release中的同名资源，因此每次正式发布都保留 `fitness-diary.apk` 这个资源名。源码ZIP不是APK，不要用GitHub自动生成的Source code安装应用。

## 读取最新版本

无需认证即可读取公开仓库的Release元数据，仍受GitHub限流与网络可用性影响。示例PowerShell：

```powershell
$repo = 'cheems-678/fitness-diary'
$latest = Invoke-RestMethod "https://api.github.com/repos/$repo/releases/latest" -Headers @{
    Accept = 'application/vnd.github+json'
    'User-Agent' = 'fitness-diary-download'
}
$apk = $latest.assets | Where-Object name -eq 'fitness-diary.apk' | Select-Object -First 1
if (-not $apk) { throw '该Release没有APK资源' }
$latest.tag_name
$apk.browser_download_url
$apk.size
$apk.digest
```

`tag_name` 为版本标签，`assets[].browser_download_url` 为可供浏览器下载的地址，`size` 为字节数，`digest` 如存在通常形如 `sha256:…`。不要把tag字符串按字典序比较为安卓升级规则；Android实际覆盖升级还取决于包名、签名和versionCode。

## 核验下载

同时下载APK和 `SHA256SUMS.txt`，在PowerShell执行：

```powershell
Get-FileHash .\fitness-diary.apk -Algorithm SHA256
```

将结果与校验文件比较。1.1.0正式APK的SHA-256为 `e790a5ab47d24932824471382bad252e10a5b9cdbffe6864a341d9554efc8d18`，大小30,743,561字节。

如尚未创建正式Release、仓库私有或资源名称不符，以上入口可能返回404。GitHub下载入口不代表应用数据同步接口；本应用没有远程读写记录的API。

接口语义参考 [GitHub官方Releases API文档](https://docs.github.com/en/rest/releases/releases)。
