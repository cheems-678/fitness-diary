# 架构说明

应用是单模块Kotlin Android项目，使用Compose、Material3、ViewModel、Room和Coil，无服务器及网络权限。

| 文件/目录 | 职责 |
|---|---|
| `MainActivity.kt` | Android入口与系统栏 |
| `DiaryViewModel.kt` | 编辑草稿、页面状态、后台IO、保存与备份操作 |
| `ui/DiaryApp.kt` | 趋势、日记、编辑、设置、照片查看与弹窗 |
| `ui/SketchTheme.kt` | 素描背景、纸片描边、字体、配色和页面过渡 |
| `ui/SketchDatePicker.kt` | 历史日期选择 |
| `ui/WeightChart.kt` | 日期坐标、曲线和点击选择 |
| `ui/SmoothCurve.kt` | 保形插值及贝塞尔段计算 |
| `data/DiaryDatabase.kt` | Room实体、查询和schema1数据库 |
| `data/DiaryRepository.kt` | 记录写入、照片私有副本管理 |
| `data/BackupManager.kt` | 完整ZIP导出、预校验与事务恢复 |

以上路径均相对 `app/src/main/java/cn/wangguanwen/fitnessdiary/`。

## 存储与隐私

日期是每日记录的唯一键，体重保存为百分之一公斤整数，可为空；感想保存全文。照片表保存UUID、所属日期、私有文件名和显示顺序，记录删除后级联处理。应用通过系统选择器导入照片，不读取整个相册、不修改原图。

照片先进入私有缓存，保存时复制到持久目录并写入数据库，失败不覆盖原记录。编辑草稿由ViewModel保留，退出未保存编辑时提示。数据库不启用破坏性升级。

系统云备份与设备迁移规则关闭，用户通过手动ZIP备份迁移。应用运行不联网；GitHub只提供源码及安装包下载，不接收应用数据。

## 备份格式1

ZIP包含 `manifest.json` 和 `photos/<UUID>.img`。清单含 `format=fitness-diary-backup`、`version=1`、导出时间、记录数组及照片大小/SHA-256。

恢复先验证版本、日期、体重、重复记录、路径、照片完整性及可解码性，限制解压大小并拒绝额外文件。验证通过并得到用户确认后，先准备新照片，再在数据库事务中完整替换；失败时保留旧数据库和旧照片，成功后才清理不再引用的应用私有文件。

## 曲线与界面

横轴使用真实日期间隔；三点及以上使用带单调约束的Hermite三次插值，转为贝塞尔路径。控制点保持在相邻数据范围内，经过所有真实点并避免过冲。双点直连，单点只显示标记，零点显示空状态。曲线只是视觉连接，不生成或保存中间日期的体重。

炭黑曲线宽2.6dp，纸白衬线5.8dp，实际点与选中日期单独标记。普通卡片纸白底不透明度约0.66，图表约0.88。背景固定并等比裁剪，页面滚动其上；背景淡化360ms，内容淡入并上移8dp约220ms。
